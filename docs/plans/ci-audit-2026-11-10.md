# CI audit and deletion plan — November 10, 2026

## Decision

Aim for a tenfold reduction in routine PR feedback time. Make the normal path affected unit
tests plus compilation where needed, with **no simulator execution and no screenshot generation**.
Delete the PR capture machinery rather than creating an optional replacement preview service.
Keep a small number of focused storage/protocol integration tests where they catch distinct faults.
Release signing, distribution and provider processing are separate from PR verification.

Air Miles is retired at the owner's request in this candidate. The rest of this document is a
proposal: it does not claim the workflow deletions, app refactors or speedup are implemented.

## Evidence and limits

- Audited the 36 workflow files, composite actions, shared selector, product adapters, build/test
  entrypoints, test target definitions, representative slow tests, hooks and live repository settings.
- Source baseline: `9027a272b62a22e4f8948d4ecccb2701e6ffb2ce` (current main when the audit began).
  The original checkout was stale; all changes use a separate worktree from current main.
- Collected 300 recent workflow records, November 10, 02:06–09:53 Pacific, with job/step details
  for 212 selected workflows. The derived initial sample contained 576 completed, non-skipped jobs.
  Also inspected up to 12 recent runs each of seven CI/delivery workflows. These overlap the first
  sample; they are not an independent population or a month-long reliability study.
- Durations below are job execution, not total PR latency or billed minutes. Latest-attempt APIs
  hide earlier attempt costs. Canceled/incomplete work is not counted as a passing speed result.
- Job creation/start timestamps show substantial scheduling delay, but dependency timing and reruns
  complicate attribution. Do not call every workflow-start-to-job-start interval runner queue time.
- Repository-managed CodeQL is an additional implicit workflow, outside the 36 committed files.
  Eight separately inspected dynamic runs had four language jobs each. Their costs are not included
  in the initial 576-job derived sample or the 137.32-minute PR example below.
- Failure steps are visible, but the job-log endpoint was unavailable to this CLI session. A failed
  screenshot run is evidence of cost/reliability burden, not proof its cause was an infrastructure flake.
- Replayed selectors against individual paths, all 2,388 baseline tracked paths, and PRs #1006/#1008.
  The 39 existing selector/policy tests pass locally; 40 pass after the Air Miles retirement case.
  No simulator, production deployment, secret lookup or live host mutation was needed for this audit.

## What actually runs for a typical PR

Thirteen workflows subscribe to every PR without top-level path restrictions. A fourteenth, Duo
screenshots, subscribes for selected Tendr/capture paths. Most unrelated jobs skip after selection,
but each workflow still pays selection/setup overhead. Workflow count is not expensive-job count.
GitHub's repository-managed CodeQL workflow additionally starts four language scans; it is not
declared in these workflow files.

- **Tendr app source:** core package tests + unsigned iOS compile; PR screenshots; component gallery
  snapshots; Duo screenshots; icon regeneration and launch-screen photography; tip-jar UI tests,
  screenshots and purchase video. RDesign tests/release-tooling/template checks are additional when
  their inputs select them, not necessarily on every Tendr screen edit.
- **Air Miles before retirement:** core tests + unsigned iOS compile + PR screenshot capture.
  Its `app.yml` declares `pr_screenshot_test`; the shared capture job accepts it.
- **Folding iOS:** contracts, localization, host package domain/storage tests, app-hosted Duo simulator
  tests and a separate PR preview capture. Backend changes run Rust tests, a release Worker build and
  workerd tests; `verify_dependents` also selects native verification even for backend-only tests.
- **Control Center Swift app:** PanelKit package tests, native formatting, app build, iPad app-hosted
  tests and iPhone platform-policy tests. Its render-only test runs inside the iPad unit suite.
  App-only source does not normally select Rust/image/infra. Server edits select Rust, image and
  the Swift/Rust contract job; they do not necessarily select the simulator portion of the Apple job.
- **Callkeep:** release-tooling tests, macOS build, unhosted XCTest and a playback harness. No iOS simulator.
- **Golink Safari:** Bun/Python tests, macOS WebKit smoke and macOS/iOS Simulator-target builds.
  Compiling for a simulator SDK does not boot a simulator.
- **Homelab:** selected Python operations, Linux runner, Darwin/Nix/host tools or CLI checks. No
  homelab work should be selected by an unrelated app. A host configuration change legitimately
  needs more than a parser/unit test, but a backup-test edit does not need every host build.
- **Ordinary docs only:** product checks skip; title/selection/bookkeeping still start. No release
  or deployment belongs on the PR path. Listing metadata under `fastlane` is deliberately not ordinary docs.

## Additional cuts beyond screenshots

### Hidden CodeQL work: 8–10 minutes of Rust analysis

GitHub's `code-scanning/default-setup` API reports CodeQL configured for Actions, Python, Ruby and
Rust, the default query suite, remote threat model, standard runners and a weekly schedule. Dynamic
PR/main runs also execute all four languages. In eight inspected runs Rust analysis took **8.12–10.05
minutes**; the other languages took **0.68–1.40 minutes**. This is static security analysis, not unit
testing or simulator execution.

For example, [Golink PR #1003](https://github.com/0x63616c/world-wide-webb/actions/runs/42827129733)
spent **9.78 minutes** on Rust analysis, although its product is JavaScript/Swift. The
[docs/migration PR #1008](https://github.com/0x63616c/world-wide-webb/actions/runs/42869573616)
spent **8.12 minutes** there. #1008 contains executable changes too; it is not a docs-only benchmark.

Replace default setup with explicit affected-language routing integrated with the CI entrypoint.
Skip unrelated Rust analysis for docs/Swift-only/website-only changes; retain relevant Rust scans
for Rust source, manifests, dependencies and analysis-configuration changes. Keep the weekly full
scan and the same query coverage. Analyze the affected codebase, not merely changed lines. This
recommendation changes event selection, not security findings or release protections.

### Remove expensive setup from cheap jobs

- Folding's domain/storage example took **6.67 minutes**: **2.87** in `folding-tools`, **2.25** in
  `swift test`, and **1.07** in release invariant tests. Its `target: apple` setup prepares Ruby,
  Bundler, Python, XcodeGen and a simulator. A host Swift package test needs none of that release/
  simulator setup. Run host tests directly, and route release invariants to a small tooling job only
  for their inputs. Cold package compilation is still real cost, so measure it separately.
- Folding backend example took **5.73 minutes**: **2.03** in tool setup and **3.55** in the combined
  check. Tool setup can install `worker-build` from Cargo on a fresh job. Cache/install the pinned
  required tool once, retain source/dependency caches, and separate host Rust tests from Worker
  packaging. Workerd tests consume the real Wasm artifact: keep the necessary build for those tests;
  do not claim all runtime tests can run without compiling the Worker.
- A normal Tendr app example took **2.87 minutes**, including **1.20** in core tests and **1.23** in
  compilation. This is not a reason to delete useful core coverage. Eliminate the additional capture
  builds and unrelated product selection first; its ordinary path is already close to the target.
- Homelab's slow sampled Darwin job took **8.73 minutes**, including **6.17** in configuration builds.
  Move it off unrelated edits; retain the actual build for changed host inputs.

### Stop testing scheduling accidents and appearance implementation details

Control Center `ClockFaceLayoutTests.swift` renders large images, scans pixels for numeral bounds,
and asserts exact RGB corner samples. Replace intended layout rules with direct assertions against
`GreenClockDial.Layout`; remove pixel/font-rasterization/color-sample checks from required CI. They
test rendering details and keep pure layout policy attached to UIKit.

Provider tests use fixed 60–100 ms sleeps, repeated yield loops, and polling loops of up to 1,000
iterations; some wait-until-started loops are unbounded. Replace these with controlled clock/transport
completion points so tests advance the relevant state explicitly and failures terminate promptly.
Do not delete race/account-isolation tests just because they are async. Folding's short independent
process/SQLite partition-fence test protects real cross-process behavior and already runs on macOS;
keep that boundary proof rather than replacing it with a mock of its own implementation.

Callkeep's downloaded ASR/speaker-model diagnostics are opt-in/skipped without their environment
inputs. They are not evidence of a routine CI model download; keep them separate and do not count
their deletion as a measured speedup. The same distinction applies to gated live CloudKit tests.

## Delete

### Six automatic visual workflows

1. `.github/workflows/pr-screenshots.yml` — delete the PR preview pipeline.
2. `.github/workflows/component-snapshots.yml` — delete the gallery pipeline, not rename it a unit suite.
3. `.github/workflows/duo-screenshots.yml` — delete the PR Duo capture workflow.
4. `.github/workflows/folding-screenshots.yml` — delete Folding PR previews.
5. `.github/workflows/tip-jar.yml` — delete screenshot/video production. Keep any unique purchase-state
   assertions as fast unit tests; catalog/provider validation stays with release tooling.
6. `.github/workflows/icon.yml` — delete the workflow and launch-screen photography. Put icon file
   validation/generator consistency in a small affected asset check; do not retain an app launch.

Remove their PR-only targets, capture lanes, app configuration keys, artifact upload steps,
selection outputs and regression tests for now-deleted preview behavior. Remove references from
`units.json`, `scripts/affected`, app manifests, generated schemes and development docs in the same change.
Preserve shared helpers only while a real release consumer still uses them. Do not blindly delete
`capture-duo-screenshots.sh` or its controller before tracing the release consumers.

### Render-only tests and other waste

- **Delete** `apps/control-center/apple/Tests/Unit/Shared/SnapshotRenderTests.swift`: 12 scenes, two
  rendering methods, PNG writes, fixed sleeps and a capture handshake. It asserts successful render
  and dimensions, not a visual baseline. It is an image-production tool inside required unit tests.
- **Delete** Folding `BuildTests/LeaderboardPreviewSnapshotTests.swift`,
  `SummaryAndEmptyBoardRenderTests.swift` and `MilestoneRenderTests.swift` after retaining any distinct
  state/layout rules as numeric/model assertions. They create screenshots/animation artifacts;
  PNG existence is not useful regression coverage for the actual appearance.
- **Delete** Tendr's `StillSnapshots` gallery target and PR-only screenshot test classes. Keep release
  screenshot classes only until the store-asset process no longer consumes them.
- **Delete** repeated phone/tablet execution of assertions that only inspect bundle policy or pure
  layout arithmetic. Read generated Info.plist/build settings once and test layout inputs directly.
- **Delete** whole-app build-for-testing when only the app compile is needed; it builds test products
  too. Give optional platform tests a separate scheme outside ordinary PR CI.
- **Remove** automatic coverage instrumentation in Folding's normal app verification if no coverage
  consumer is identified (`gatherCoverageData: true`). Do not invent a coverage service to justify it.
- **Remove** duplicate release-note checks in Callkeep's workflow/script combination and repeated
  release-time package tests when the same inputs already have successful CI evidence.
- **Remove** broad pre-push Rust/operations execution for unrelated edits. Current root hooks
  delegate to Control Center regardless of product, including docs changes. Keep fast staged secret,
  privacy and syntax guards, routed by affected files.
- **Retire** the migration-only `homelab-runners.yml` benchmark matrix and `homelab-runner-recovery.yml`
  canary-branch triggers after checking their remaining operator callers. Keep actual recovery
  commands in their owning product; no permanent parallel benchmark pipeline is needed.
- **Delete** source-text/YAML-shape tests that merely assert exact names, runner labels or step order
  with no independent behavior. Retain tests of selection, failed/skipped gates, authentication before
  mutation, immutable artifact identity, retry ownership and public/private publication behavior.
  Do not delete the entire tooling test directory: its tests currently run in seconds.

## Make useful tests independent of simulators

**Folding is the largest refactor opportunity.** `FoldingKit` already supports macOS host tests.
Extract presentation/account-fencing/history-loading/export state and retry decisions from the
app target into product-local host-testable code. `PresentationTests.swift` contains substantial
business behavior currently paying for an app host. Move journal/restart/contention assertions from
`AppIntegrationTests.swift` into FoldingData tests with temporary SQLite and controlled clocks.
Keep real SQLite where transactions/leases matter; replace wall-clock waits with explicit async
completion and an injected clock/sleeper. Leave UIKit, AppIntents and device composition in thin adapters.

`LiveCloudKitTests.swift` is behind `LIVE_CLOUDKIT_INTEGRATION`; it is **not evidence that normal CI
waits on live iCloud**. Keep a targeted explicit platform diagnostic only if it has an owner/use;
it should not become routine CI. Pure account/sync policy belongs in host unit tests.

**Control Center:** move provider state/routing/update/timer logic out of `@testable import Panel`
into a small product-local host-testable module beside PanelKit. Keep PanelKit focused on transport,
wire models and shared client state. Providers that only need Foundation and PanelKit should not
require an iPad application. Parameterize time, permissions and native adapters; do not mock every
internal method. Test size/layout decisions as functions of inputs instead of drawing screens.

**Tendr:** keep StillCore tests and extract unique tip/presentation state from UI tests. An app screen
change needs a compile check, not a screenshot tour. RDesign already has macOS package tests; run
them only for RDesign inputs/consumers, not because a release script elsewhere changed.

**Callkeep:** preserve its existing unhosted test approach. Separate playback/device/model-download
diagnostics from ordinary business/persistence tests; don't add simulator-like UI machinery.

**Golink Safari:** split its existing check handler into cheap Bun/Python policy tests and platform
compile/WebKit checks. Scope each to extension logic versus native wrapper inputs. Do not boot iOS
for shortcut parsing or redirect decisions.

**Homelab:** keep operations tests, selected Rust tests and affected configuration evaluation/builds.
Do not replace Nix validation with a mock that cannot detect a broken actual host configuration.
Package source filters and selectors should agree on real input dependencies. Narrow broad
`homelab/**` Darwin checks before introducing more cache/concurrency machinery.

No universal cross-app core package or repository-wide architecture rewrite is proposed. Products
already have physical boundaries; extract only code needed to remove expensive app-host dependencies.

## Fix selection before optimizing runners

The baseline manifest has 20 units and **115 tracked non-doc paths without an owner**. For any
unmapped input, `select_units.py` selects every unit and every granular check. Examples include
`.gitignore`, `.github/workflows/pr-conventions.yml`, capture helpers, and site publication scripts.
`shared_verify` also selects everything for all `scripts/ci/**` and all root Fastlane inputs.

1. Use the existing `units.json` as the ownership source; remove duplicated policy in product adapters
   and `scripts/affected` as their remaining discovery/capability needs are integrated. Do not add a fourth selector.
2. Map workflow/action/tool inputs to actual consumers. Selector unit tests test the selector; they
   need not compile every app. A shared runtime change selects real consumers, not all products by default.
3. Cover tracked executable/configuration paths. For an unknown changed path, fail one cheap ownership
   check with the path named, rather than silently passing or launching the entire monorepo.
   Explicitly classify docs, developer config, design assets and retired products too.
4. Keep docs exclusions precise. `documentation()` currently treats any path containing `fastlane`,
   `listing`, `metadata` or `screenshots` as potentially executable product input before its docs test;
   retained historical screenshot docs can therefore be classified unexpectedly.
5. Split units/checks by native core, native compile, server, contract, tooling and release assets.
   Backend-test changes should not automatically invoke native simulator checks. Wire-contract changes
   should run relevant producer/client contract tests without producing screenshots.
6. Make one cheap always-running required dispatcher/gate select affected jobs/reusable workflows.
   Unrelated product workflows should not start. Preserve fail-closed selected success/skipped rules,
   cancellation and merge-base/rename/deletion handling already present in the selector.
7. Never use only top-level path filters on required workflows: GitHub can leave missing required
   checks pending. If a product workflow remains separate temporarily, require its aggregate gate
   and let jobs skip; ultimately require the single repository aggregate instead.
8. Separate verification from delivery inputs. Test-only and docs changes never publish. Deletions
   and both sides of moves remain first-class inputs; don't infer ownership only from files remaining at HEAD.

Air Miles removal adds a narrow retired-path rule so deleted app paths are not reclassified as
unknown and used to verify every remaining product. Historical migration records remain historical.

## Releases and screenshots

Store screenshots are release assets, not a reason to run PR UI suites. Apple documents image
formats, dimensions and presentation, not an obligation to use our simulator pipeline. Reuse approved
assets when still accurate. If UI/locale inputs changed, update the necessary assets as release work.
Apple allows the highest required resolution to scale for other equivalent sizes; do not assume
every appearance/device/locale combination needs independent capture.

Direct SwiftUI rendering is useful where faithful, but **not a universal simulator replacement**:
ImageRenderer excludes many UIKit/AppKit/Core Animation-backed contents. Glass/system UI may need
a device or simulator for accurate images. Do not build a new renderer unless actual store-asset
needs justify it. A physical device/manual capture is a valid production process too.

- Tendr `testflight.yml` couples beta publication, repeated RDesign tests, phone/Duo capture, listing
  upload and App Review. Split beta distribution from store asset/submission work. Standard iOS
  delivery was not enabled in the repository variables read during this audit; distinguish configured
  code from observed active work (the sampled TestFlight runs were skipped).
- Folding release couples Worker publication, native beta, capture and submission in a Mac job.
  Split Worker delivery onto Linux and keep Mac acquisition only for native signing. Separate beta
  success from store submission; one inspected delivery spent 7.65 minutes in beta and then failed
  after 13.40 minutes in submission. Preserve the already-successful beta on retry.
- Folding release policy explicitly requires `simulator` in `release-config.json`, `check_evidence.rb`,
  `release_operations.rb`, `automatic_release.rb` and `continuous-delivery.rb`. Update these consumers
  together when replacing the simulator gate; deleting only the workflow will break delivery.
- Replace Tendr's dedicated up-to-80-minute Linux polling job with a successful-CI completion trigger,
  bound to the exact source and required checks. Preserve an explicit manual release route.
- Keep current source-bound image/Worker artifacts, processed-upload receipts, monotonic build numbers,
  single publisher per product and no automatic retries of physical/provider mutations.
- Control Center promotion now writes a tested image pin into homelab desired state; it no longer
  directly deploys the mini. Keep one host mutation owner. A separate pin PR legitimately needs
  affected host/service validation, not every app's tests or a full recovery rehearsal.
- Keep Homebrew signing/notarization/download integrity and backup/SQLite preservation checks at
  their actual delivery boundaries. Those are not screenshot overhead.

## Repository setup

- Active `pipeline-required-checks` enforces **Conventional Commit title, changes, typecheck,
  test-unit, build-and-test**. These are the Control Center workflow's contexts. Folding, Standard
  iOS, Callkeep, Golink, Homelab and Sites gates are not individually required by this ruleset.
  The fast replacement must cover all selected products, not merely make the old five green.
- The active rule named `main-require-codeowner-approval` has **no rules**. CODEOWNERS comments claim
  mandatory review that this rule does not enforce. Remove misleading configuration/comments or
  choose a deliberate review policy; do not add bureaucratic approvals as a speed project.
- Legacy branch protection returns 404, but active rulesets still enforce checks and prevent
  non-fast-forward/deletion. Do not interpret that 404 as an unprotected main branch.
- Default Actions token is read-only and cannot approve reviews: retain. Actions allow all providers,
  SHA pinning is not required and pins are mixed. Finish pinning the actions actually retained;
  keep Renovate's existing weekly schedule/three-PR cap rather than adding another updater.
- `prod` and `production` environments both allow main and have branch policy, not required human
  reviewers. Consolidate only after inventorying secret/variable consumers. Do not move signing
  credentials into PR jobs. Repo runner inventory returned zero self-hosted runners; workflows now
  target hosted labels, so adding homelab runner capacity is not the first optimization.
- Automatic squash/merge are enabled; rebase is disabled. Keep release identity tied to the tested
  main revision. Do not reuse a PR artifact solely because a branch name matches.
- Cache usage was approximately **10.72 GB across 27 entries**. Existing source-aware Rust snapshots,
  Docker Cargo-cache transfer and bounded Nix caching already exist. Inspect cache restore/save
  time before adding another cache system. Folding Apple setup repeatedly installs tools/bundles and
  creates a simulator even for host-domain tests; split setup by actual target and cache dependencies.
- Root `tools/setup`, `tools/check` and hooks still principally serve Control Center, although
  `scripts/dev` is product-aware. Make the normal developer command use the same affected policy as CI.
  `.wtp.yml` also unconditionally copies an optional missing Claude settings file: worktree creation
  emitted a warning after otherwise successful setup. Remove the obsolete copy or make its optional
  behavior explicit; don't let machine-local agent setup add noisy/fallible project requirements.
- Legacy site publication still points at the deleted `0x63616c/apps` repository and is enabled.
  This is tracked by #1007 and the owner accepted interim URL loss. Remove the dead legacy publication
  job/secret consumer while delivering the replacement through that issue; do not resurrect the repo.

## Implementation order and acceptance

1. **Delete capture waste.** Remove the six PR workflows and render-only tests/targets. Update their
   selectors/schemes/callers and release policy where necessary. Do not replace them with other capture jobs.
2. **Repair selection and enforcement.** Complete ownership, cheap unknown-path failure, one dispatcher,
   all-product aggregate, and scoped developer hooks. Migrate required contexts only after the new
   gate runs in parallel and its success/failure/skip behavior is proven. Never temporarily disable checks.
3. **Extract expensive app-hosted logic.** Folding first, then Control Center. Retain independent
   business/storage assertions in host package tests; replace sleeps with deterministic coordination.
   Remove simulator execution from required PR CI once those assertions have moved.
4. **Slim build/release work.** One affected unsigned compile; expensive release packaging only when
   relevant; no store capture on beta-only delivery; eliminate polling and repeated checks/setup.
5. **Measure, then tune residual setup/cache cost.** No new runners, broad scheduled test matrices or
   extra simulation framework until the simpler path has real measurements.

Proposed acceptance targets, not achieved measurements:

- Docs-only: one cheap check, ideally under 60 seconds total; zero product jobs/releases/host activation.
- Pure business/test changes: affected unit suites, roughly 30–90 seconds of execution; normal
  PR feedback target around two minutes. No simulator startup or screenshot/video artifact.
- Native wiring/UI changes: affected host tests plus one unsigned compile, target two–five minutes.
  A cold full Xcode build is recorded separately, not disguised by a warm-cache benchmark.
- Backend changes: affected Rust/Worker tests and necessary contract/packaging checks. No unrelated
  app compile; no native simulator. Provider packaging is not required for an assertion-only test edit.
- Infrastructure/host changes: actual affected configuration validation/build, not every product.
  Expensive real changes may exceed the routine PR budget; measure them independently.
- Tenfold improvement: compare matched before/after scenarios from current 24–50-minute workflows,
  including scheduling and setup in PR feedback, and also report total runner execution. Use successful
  runs, record cold/warm state and retries, and report median/p95 only with adequate samples. Deleting
  ~63 of ~137 sampled job-minutes alone is not a tenfold speedup; selection/refactoring must do the rest.
- Validate representative docs, per-app source, test-only, shared action, contract, rename/deletion,
  unknown path, infrastructure and release-asset scenarios with small fixtures. Reuse existing selector
  and gate tests. Do not create hundreds of end-to-end simulations to prove a simpler pipeline.
